# AppleExtended-Modified

[简体中文](README.md) | [English](README.en.md) | **日本語**

Minecraft 1.12.2 / Forge 向けに、HabQi が 2026 年に開発・保守している AppleExtended の個人改造版です。AppleExtended のコミット `d40d973` をベースとしており、現在のビルドバージョンは `1.0.0` です。

- [本改造版のリポジトリ](https://github.com/HabQi/AppleExtended-Modified)
- [改造元の AppleExtended](https://github.com/ringo-1234/AppleExtended)
- [ソースコードからのビルド方法](BUILDING.md)
- 改造元の日本語 README と謝辞は、本書の末尾に保存しています。

AppleExtended は RealTrainMod（RTM）、NGTLib、MCTE の非公式改造プロジェクトです。本リポジトリでは、ビルドに必要な fixRTM のソースコードを補完し、乗客の操作、車両の同期、描画処理を変更しています。以下は、上記のベースコミットに対する本改造版の変更内容です。

## 主な変更点

### 車内歩行と車両間の移動

- 車内を歩行するための床エンティティを追加しました。乗客は車両のローカル座標上で移動し、列車の位置、向き、ピッチ、ロールに合わせて位置が更新されます。
- メインハンドに切符を持ち、他のエンティティに乗っておらず、スニークしていない状態で列車を右クリックすると、歩行可能エリアに乗り込みます。車内では通常の移動キーを使用します。
- 連結された隣接車両への移動に対応しました。両車両の該当する連結端で通行が許可され、接続位置が距離と通路幅の条件を満たす必要があります。
- クライアント側の移動予測、サーバー側の入力処理、位置補正、新たに追跡を開始したプレイヤーへの乗客位置の同期を追加しました。
- 乗客位置と一人称カメラの補間、車体の傾きへの追従、歩行アニメーションを調整し、バニラの移動処理と車内移動処理が重複して適用される問題に対処しました。
- 旧 `TrainPlatformHandler` と `PlayerCameraTrain` を削除し、新しい乗客・車内移動処理に置き換えました。

歩行可能エリアはモデル設定で指定する長方形です。車両モデルから座席、壁、複数階の床を自動認識するものではありません。車種に合わせて中心位置、高さ、長さ、幅を調整してください。

### 乗客の座り姿勢・寝姿勢

立ち姿勢、座り姿勢、寝姿勢を追加しました。歩行可能な床の上で切り替えられ、他のプレイヤーにも同期されます。姿勢の状態は、降車、ログアウト、死亡、ディメンション移動などの際に解除されます。

| 操作 | デフォルトキー | 条件 |
| --- | --- | --- |
| 座り姿勢にする | `G` | 歩行可能な床の上にいる |
| 寝姿勢にする | `H` | 歩行可能な床の上にいる |
| 立ち姿勢に戻る | ジャンプキー（デフォルトは `Space`） | 歩行可能な床の上にいる |
| 寝姿勢の高さを上げる | `=` | 寝姿勢のとき。長押し可能 |
| 寝姿勢の高さを下げる | `-` | 寝姿勢のとき。長押し可能 |

キーはゲーム内の操作設定で変更できます。他の Mod と競合する場合は割り当てを変更してください。姿勢操作キーの表示文を、簡体字中国語、繁体字中国語、日本語、英語、スペイン語、ロシア語に追加しました。

### 乗降車・ログアウト・再ログイン処理

- 降車位置の候補を記録し、降車時の衝突判定と配置処理を調整しました。
- プレイヤーデータの保存時に RTM の乗車関係と復帰位置を処理し、プレイヤーの保存データに含まれる列車エンティティのコピーへ直接依存しないようにしました。
- ログアウト時には列車から降車させます。再ログイン時には有効な復帰位置を使用し、歩行用の床への参照を修復します。
- 床エンティティ専用のトラッカーを追加し、乗客一覧、初期位置のスナップショット、その後の同期を管理します。

この復帰処理は降車と再ログイン時の配置を扱います。再ログイン後に車内の乗車状態を自動復元する機能はありません。

### 車両・線路の描画調整

- **車両テクスチャの読み込み**：バックグラウンドでテクスチャをデコードし、OpenGL へのアップロードは描画スレッド上で行います。待機中のテクスチャは 1 フレームにつき最大 1 枚アップロードします。車両、台車、列車模型の展示ブロックで共通の準備完了チェックを使用します。
- **視錐台カリング**：車体、台車、線路、電線の可視判定を追加・調整し、視野外の描画を減らします。プレイヤーが乗車中の車両、不正なバウンディングボックス、シェーダー関連の描画段階には専用の処理があります。
- **線路描画リソースの構築**：タスクキュー、ジオメトリのスナップショット、バックグラウンドでの静的メッシュ構築、メインスレッドでのアップロード処理時間の制限を導入しました。無効になったタスク、再構築、リソース解放も処理します。
- **線路 LOD**：表示距離に応じた代替の線路モデルをモデルパックから指定できます。`lodModels` がない場合は、引き続きメインモデルを使用します。
- **線路の表示条件**：描画前に、線路の端点が描画距離内にあり、該当チャンクが読み込まれているか確認します。長い線路は、両端が条件を満たすまで表示されない場合があります。
- **リソース管理**：ディスプレイリスト、VBO、VAO、バッファー、シェーダープログラムの解放処理を補完しました。モデルリソースの破棄と被写界深度カメラ用シェーダーの解放を調整し、変換行列を使って法線を変換します。
- **シェーダー向けインターフェース**：RTM の発光描画パスに `rtmEmissivePass` マーカーを提供し、ローカルプレイヤーが乗車中の列車について `rtmTemporalEntity` / `rtmViewToPreviousView` による時間的再投影データを提供します。シェーダーパック側で明示的に利用する必要があり、すべてのシェーダーパックへの対応を意味するものではありません。
- **乗客の描画**：車内のプレイヤーモデル、一人称の手、手持ちアイテムの明るさを調整し、描画後に関連する状態を元に戻します。

これらの変更は、読み込みや再構築時の引っかかりを減らし、車両表示を改善することを目的としています。本リポジトリには性能ベンチマークはありません。実際のフレームレートやモデルパックとの互換性は、実機での確認が必要です。

### 警笛と線路の撤去

- キー操作とマクロによる警笛に専用の再生処理とネットワーク上の識別情報を追加し、通常の車両音に警笛の可聴範囲が誤って適用されないようにしました。
- 警笛のデフォルト可聴範囲を 16 ブロックから 256 ブロックに変更しました。可聴範囲が個別指定されたエンティティ音には、距離に対する線形減衰を適用します。
- AppleLib 設定の `sound_range` カテゴリにある `hornSoundRange` で範囲を変更できます。既存の設定値はそのまま使用され、デフォルト値の変更によって自動的に上書きされることはありません。
- プレイヤーが大型線路を手動で撤去する際は、メインハンドに RTM の鉄の金鋸（`iron_hacksaw`）を持つ必要があります。撤去に成功すると道具の耐久値を消費します。

### マルチプレイと互換性

- 車両の移動情報を、そのエンティティを追跡しているプレイヤーへ送信します。新たな追跡開始時には、車両状態と乗客の乗車関係も同期します。
- 車両移動パケットをクライアントスレッドで処理し、位置、向き、ロールに同じ状態スナップショットを使用します。
- クライアントでのエンティティ ID の再利用、無効な台車参照、古いエンティティの削除通知が置き換え後のエンティティ追跡に影響する問題に対処しました。
- ReplayMod の検出をリフレクション呼び出しに変更し、そのクラスへの直接的なコンパイル依存を減らしました。ReplayMod のリプレイ再生との互換性テストが完了したことを意味するものではありません。
- 歩行・姿勢用パケットを追加し、警笛パケットの形式も変更しました。クライアントとサーバーには、本改造版の同じビルドを使用してください。AppleLib は相手側のバージョン文字列がローカルと一致するか確認します。

## モデルパックの設定

### 車内の歩行可能エリア

列車モデルの設定で `walkable` を追加または調整します。次の JSON フィールドを既存の設定に組み込めます。

```json
{
  "walkable": {
    "enabled": true,
    "center": [0.0, 1.3, 0.0],
    "length": 0.0,
    "width": 3.0,
    "allowCarriageTransfer": true,
    "transferEnds": [true, true],
    "transferWidth": 1.0
  }
}
```

| フィールド | デフォルト値 | 意味 |
| --- | --- | --- |
| `enabled` | `true` | 車内の歩行可能エリアを有効にするかどうか |
| `center` | `[0.0, 1.3, 0.0]` | 車両ローカル座標でのエリア中心。単位はブロック |
| `length` | `0.0` | エリアの全長。0 以下の場合は `trainDistance × 2` から算出 |
| `width` | `3.0` | エリアの幅。単位はブロック |
| `allowCarriageTransfer` | `true` | 車両間の移動を許可するかどうか |
| `transferEnds` | `[true, true]` | RTM の連結端 0、1 それぞれの通行許可 |
| `transferWidth` | `1.0` | 各車端の中央に設ける通路の幅。単位はブロック |

`walkable` を記述していない車両にもデフォルトのエリアが適用されます。車内歩行に適さない車両では、`"walkable": { "enabled": false }` を明示的に設定してください。

### 距離別の線路モデルと非同期構築

線路設定の `lodModels` 配列で代替モデルを指定できます。各要素には `distance`、`modelFile`、および省略可能な `textures`、`rendererPath`、`vertexShaderPath`、`fragmentShaderPath` を指定します。`distance` は、線路のコアからそのモデルの使用を開始する距離で、単位はブロックです。複数のしきい値に達している場合は、適用可能な中で最も遠距離向けのモデルを選択します。

スクリプト付き線路で非同期の静的メッシュ構築を利用するには、`supportsAsyncStaticMesh = true` を明示的に宣言する必要があります。有効にする前に、そのスクリプトが静的ジオメトリのスナップショットに適しているか確認してください。宣言のないスクリプトは従来の構築処理を使用します。本リポジトリでは、モノレール、ケーブル、桁、高架、標準線路などの 7 つの内蔵スクリプトにこの宣言を追加しています。

## 調整可能なクライアント設定

次の設定は `config/fix-rtm.cfg` にあり、どちらもデフォルトで有効です。

| カテゴリ | 設定項目 | 役割 |
| --- | --- | --- |
| `model_loading` | `asyncVehicleTextureLoading` | 車両テクスチャのバックグラウンドデコードとフレームごとのアップロード |
| `better_rtm` | `vehicleFrustumCulling` | 車両と台車の視錐台カリング |

## fixRTM ソースとビルド構成の整理

- `com.anatawa12.fixRtm` 配下の不足していた Java / Kotlin ソース、API、補助ファイルと、関連する言語・テクスチャリソースを補完しました。第三者のコードを含むため、元の作者表記とライセンス表示を保持しています。
- fixRTM の一部を Kotlin 1.4、Minecraft のマッピング、Java からの呼び出しに適合させ、本改造版の乗客復帰、描画、床エンティティ追跡処理を組み込みました。
- ビルドには Java 8、Gradle 5.6.4、ForgeGradle 3.0.197、Kotlin 1.4.32 を使用します。同梱ライブラリとその推移的依存関係は、明示的なパッケージ設定で収集します。
- サービス検出用の定義を統合して WebP ImageIO などのサービスを保持し、依存ライブラリごとにライセンス本文と帰属表示を保存します。また、Sai と jbsdiff のライセンス表記を修正しました。
- 通常のビルドは `build/libs/` に出力し、ゲームやサーバーのディレクトリへ自動コピーしません。手動コピーの方法は [BUILDING.md](BUILDING.md) を参照してください。
- 現在、ルートプロジェクトでは `cr/` を有効にしておらず、ビルド設定のみを参考として保持しています。`src/main/kotlin` にある同名の `CommandRTM` も、現在の Kotlin コンパイル対象ディレクトリには含めていません。

元の作業環境にあった `rtm-patches` / `ngtlib-patches` ディレクトリは、本リポジトリの作業ツリーから削除し、ローカルのリポジトリ外へバックアップしました。現在のプロジェクトは対応する Java ソースを直接コンパイルするため、これらのパッチファイルをビルド入力として使用しません。

## 使用方法と検証状況

Minecraft 1.12.2 と対応する Forge 環境を使用し、自分でビルドした Mod の JAR をインスタンスの `mods` ディレクトリに配置してください。本プロジェクトには RTM、NGTLib、MCTE、fixRTM 関連のコードが含まれるため、同じ Mod やクラスを含む別の JAR を同時に導入しないでください。

機能説明は現在のソースコードに基づいています。ルートプロジェクトのコンパイル、JAR の再難読化、パッケージ内容の確認は実施済みですが、ゲーム内での一通りの動作、マルチプレイでの車両間移動、ログアウト後の再ログイン、ReplayMod、各種モデルパックとシェーダーの組み合わせは、引き続きテストが必要です。ビルド内の Test タスクは現在無効であり、ビルド成功はゲーム内機能の検証完了を意味しません。
